### What's Still Blocked
**Persistent crash at elr=0x3AF610A8** — same address across ALL code paths.

### Key Experiment Results
**Bypassed `component::init_all` AND `init()`** — kernel still crashed at same ELR:
```
[KM.main] start
[KM.main] skip component::init_all
[KM.main] skip init()
[KM.main] after init
[CRASH at elr=0x3af610a8]
```
**Conclusion**: Crash is NOT in `init()` or `component::init_all`. It happens AFTER both are bypassed, at `smp::register_ap_entry()`.

**With BOTH skipped BUT component::init_all active** — also crashed at same address:
```
[KM.main] start
[KM.main] after component::init_all
[KM.main] skip init()
[KM.main] after init
[CRASH at elr=0x3af610a8]
```
This suggests `smp::register_ap_entry()` is the crash point, OR the crash happens BEFORE these functions are reached (e.g., in the `#[ostd::main]` wrapper or `call_ostd_main`).

### The Persistent ELR=0x3AF610A8
- ESR=0x02000000 = Instruction Abort (MMU fault on instruction fetch)
- lr (x30) = 0x3af610a8 = same as elr (crashed while returning to or inside a function)
- Code at elr: `3af61060` (instruction causing fault)
- x29 = 0x3 (corrupted frame pointer)
- **The crash address 0x3af610a8 is NEVER REACHED by our pl011_puts markers** — all our markers print correctly up to `[init.9]` in OSTD and `[KM.main] start` in kernel main. The crash happens AFTER our last marker.

### Architecture
- `call_ostd_main()` → `crate::init()` → `__ostd_main()` (generated by `#[ostd::main]` macro)
- `__ostd_main()` → kernel's `main()` → `component::init_all()` → `init()` → `smp::register_ap_entry()` → ...
- On RPi3: smp::init, activate_kernel_page_table, timer::init, io::init are ALL SKIPPED
